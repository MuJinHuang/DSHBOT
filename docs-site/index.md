# DSHBot Rooms

**在 DSH 里开一个房间，拉几个有岗位的 Bot 同事进来，说一句话，它们分头干活。**

你只需要：定目标 → 批计划 → 验产物。

## 它解决什么问题

普通多 Agent 对话最后常常变成"几个 Bot 互相复述"，而且没人知道事情到底做没做成。
DSHBot 把协作压成四个可检查的环节：

| 环节 | 做法 |
|---|---|
| **房间 = 任务** | 一个目标 + 多条验收；`file:路径` / `cmd:命令` 由机器判，0 token |
| **计划先给人看** | confirm 模式下先出计划；可全批，也可勾选部分批准 |
| **依赖有顺序** | 总管用 `[依赖:@名字]` 标注，房间按 DAG 分层执行，上游结论自动交给下游 |
| **交付可追溯** | 独立快照仓库、diff、回滚、产物预览、审计 JSONL |

## 核心能力

- **Bot 库**：岗位、专长、输出规范、工具集、模型；导出/导入 JSON
- **团队模板**：常一起干活的几只 Bot 存成团队，建房一键拉入
- **计划 DAG**：链式/汇聚依赖，多依赖点选，环与缺失依赖直接拒绝；失败任务可单件重跑
- **每 Bot 模型**：库/房间可选模型 + 推理强度，保存前校验，开跑前装到会话
- **交付面板**：文件 tab 直接读产物；变更文件看 diff
- **搜索 / 审计**：搜全量历史；按类型筛工具调用
- **备份 / 恢复**：整库 JSON，恢复前自动备份
- **预算**：单轮 / 单人 / 房间三档，界面可改，到线拒跑

## 兼容与限制

- 在 **DSH 0.2.1-rc.5**（Windows）验证；依赖 DSH 的 `webServer` / `agents` / `sessions` / `sessionController`
- 安装 Release 不需要 Node / pnpm / Python / 管理员权限；`git` 可选（没有时快照/diff/回滚降级）
- 房间内审批卡、硬写锁、逐条工具事件推流受 DSH 接口限制，暂不做
