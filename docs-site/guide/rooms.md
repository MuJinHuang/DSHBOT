# 五分钟上手

## 1. 建一个房间

侧栏进入「房间」→「＋ 新建房间」，填：

- **名称**：如「电源模块交付」
- **目标**：一句话说清要交付什么
- **验收**：一行一条。要文件就写 `file:docs/交付.md`，要命令通过就写 `cmd:pnpm test`
- **工作目录**（可选）：填了 Bot 才能读你的项目

> 新房间默认是**空房**：不会自动塞一只没岗位卡的 Bot。可以手动拉人，或直接点「创建示例房间」。

## 2. 拉 Bot

右侧「＋ 拉一个 Bot」：

- 从 **Bot 库**选角色卡；
- 或临时建一只：名字、岗位、专长、输出规范、工具集（agent preset）、模型。

一个 Bot 一个会话，互不串历史。

## 3. 说一句话，出计划

直接说需求。confirm 模式下总管会：

1. 拆成几件事；
2. 用 `@名字` 指向执行者；
3. 有先后依赖时，在下游任务末尾加 `[依赖:@名字]`。

计划卡里可以：

- 勾选**只批准其中几件**，没选中的标 `skipped`；
- 改每件事的**依赖**（下拉选择上游，或清空）；
- 全部否决。

## 4. 执行与交付

批准后按依赖分层跑：上游的结论会自动拼进下游的上下文，被阻塞的下游会标 `blocked`，不会空跑。
失败/阻塞的任务卡可以点「重跑」单独重试，不用整批重来。

跑完看「交付结论」：

- 每条验收：pass / fail / 存疑；
- 变更文件 → 点开看 diff；
- 「文件」tab → 直接读工作区产物，`.md` 按 Markdown 渲染；
- 「审计」tab → 按类型筛工具调用，导出 JSONL；
- 版本 → 回滚到某个快照。

## 5. 搜索与备份

- 消息区右上角搜索框：搜全量历史，结果带上下文片段；
- 左侧「整库」→ **备份**下载 JSON；**恢复**会二次确认，并先把当前库自动备份到 `backups/`。

## 常用操作

| 操作 | 位置 |
|---|---|
| 改房间目标/验收/预算/执行模式 | 头部「编辑」 |
| 改/移出成员 | 右侧成员卡「改」「移出」 |
| 另存为房间 | 头部「另存为」 |
| 导出 Markdown / 审计 | 头部「导出」「审计」 |
| 停止当前一轮 | 发送中的「停止」 |
| 暂停 / 归档 / 仅 @ 响应 | 头部按钮 |
