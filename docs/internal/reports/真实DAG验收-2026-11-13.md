# 真实模型 DAG 验收（2026-11-13）

## 目的

验证不是假宿主：真实 DSH + 真实模型 + 两个执行者 + A→B 依赖 + 文件交付 + 验收。

## 环境

- DSH 0.2.1-rc.5，Windows
- profile：`dshbot-dev`
- 数据目录：临时目录（不碰桌面端）
- 模型：部署默认 `deepseek-account/deepseek-flash`
- 脚本：[`spike/live-dag-check.mjs`](../../../spike/live-dag-check.mjs)

```powershell
$env:DSHBOT_DATA_DIR="$env:TEMP\dshbot-live-dag"
dsh --profile dshbot-dev --port 54873 --no-open
node spike/live-dag-check.mjs --port 54873
```

## 结果

```text
room=room_e0c8b04f5c9c
plan: 老周 / 小柯
执行完成，开始验收
验收：验收点 2/2 通过；变更文件 2 个
文件：a.md、b.md
a.md=A
b.md=AB
真实 DAG 验收通过
```

- 总管真实模型拆出两件任务；
- 批准时强制 `小柯 → 老周` 依赖；
- 小柯写出的 `b.md` 内容是 `AB`，说明它读到了老周的上游产物；
- `file:a.md`、`file:b.md` 两条机器验收都通过；
- 任务卡先是 `running`，执行完变 `done`。

## 注意

- 这个脚本会**花 token**，只在发布前手工跑，不进 CI；
- 用户消息里不要写裸 `@名字`，否则会被房间当成直接派活；脚本用“at 符号”描述。
- 首次跑时曾因为用户消息里出现 `@派活` / `[依赖:@老周]` 被 mentions 解析拦下，已修正脚本。
