# 发布包本地验证（2026-11-13）

## 目的

不用等 GitHub tag，先验证 release 产物本身能装进一个全新 profile 并加载插件。

## 构建

```powershell
pnpm build
$stage="dist/dshbot-plugin-0.2.0"
# 复制 lib / package.json / cordis.patch.yml / icon.svg / locale / README / LICENSE / CHANGELOG
Compress-Archive -Path $stage -DestinationPath "dist/dshbot-plugin-0.2.0.zip" -Force
Copy-Item LICENSE packages/plugin/LICENSE
cd packages/plugin; pnpm pack --pack-destination ../../dist
```

产物：

```text
dist/dshbot-plugin-0.2.0.zip   64,554 bytes
dist/dshbot-plugin-0.2.0.tgz   61,806 bytes
```

## 全新 profile 安装

```powershell
dsh plugin --profile dshbot-release-test add "file:D:\Desktop\DSBOT\dist\dshbot-plugin-0.2.0.tgz"
```

- 自动创建 profile，`dsh.profile.bundles` 包含 `@dshbot/plugin`；
- 包内文件：`lib/`、`locale/`、`cordis.patch.yml`、`icon.svg`、`LICENSE`、`README.md`、`package.json`。

## 启动验证

全新 profile 默认只带 `@deepseek-ai/dsh-base`，缺少 `webServer`/`sessionController`，插件会 pending。
补上 `@deepseek-ai/dsh-web-app` bundle 后启动：

```text
[dshbot] host side loaded, api at /dshbot/api
dsh web: http://127.0.0.1:54879/?token=...
```

```text
GET /dshbot/api/health  → { "ok": true }
GET /dshbot/api/models  → deepseek-account
```

验证后已删除 `dshbot-release-test` profile 与临时数据目录。

## 结论

- tarball 安装路径、bundle 自动注册、插件加载都通过；
- 干净 profile 需要 `dsh-web-app`（这是 DSH 启动配置，不是插件问题）；
- 真正发布前仍建议在另一台干净 Windows 上再装一次 zip。
